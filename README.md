# Organization Knowledge
# 組織内人脈・知識グラフ型 名刺OCR AIシステム

**Phase 1：名刺登録 → AIによる読み取り → 確認 → 保存**

名刺の画像をアップロードすると、Google の Gemini AI が記載事項を項目に分け、
人が内容を確認してから登録できます。

## 2. Gemini APIキーを取得する

「APIキー」とは、Google のAIを使うための鍵のことです。

1. https://aistudio.google.com/apikey を開く
2. Google アカウントでログイン
3. 「Create API key」または「APIキーを作成」を押す
4. `AIzaSy...` で始まる長い文字列が表示されるので、**コピーしてメモ帳などに一時保存**

> **重要**
> このキーは、絶対にファイルに書いたりGitHubに上げたりしないでください。
> 次の手順で、Cloudflare の安全な場所に預けます。

**使いすぎ防止の設定（推奨）**
Google Cloud Console の「お支払い」→「予算とアラート」で、月額の上限（たとえば500円）を
設定しておくと安心です。デモ用途なら無料枠の範囲で収まることがほとんどです。

## 3. Cloudflare Workers を作る（APIキーの保管場所）

「Workers」は、小さなプログラムをインターネット上で動かしてくれる無料のサービスです。
ここに **APIキーを隠しておく** ことで、ブラウザ側にキーを置かずに済みます。

### 3-1. アカウントを作る

https://dash.cloudflare.com/sign-up でメールアドレスとパスワードを登録します。

### 3-2. Worker を作る

1. 左メニューの **「Compute (Workers)」** →**「Workers & Pages」** を開く
2. **「Create」**（作成）→ **「Start with Hello World!」** を選ぶ
3. 名前を `meishi-ocr` と入力して **「Deploy」**（デプロイ）を押す
4. 作成が終わると、次のようなURLが表示されます。**これをメモしてください**

   ```
   https://meishi-ocr.あなたの名前.workers.dev
   ```

### 3-3. 中身を書き換える

1. 画面の **「Edit code」**（コードを編集）を押す
2. 左側のエディタに書かれている内容を **すべて削除**
3. このプロジェクトの `worker/worker.js` の中身を **すべてコピーして貼り付け**
4. 貼り付けたコードの上のほうにある、次の1行を書き換えます

   ```js
   "https://YOUR-NAME.github.io",   // ← ここ
   ```

   `YOUR-NAME` を、あなたのGitHubのユーザー名に変えます。
   たとえばユーザー名が `taro-yamada` なら

   ```js
   "https://taro-yamada.github.io",
   ```

   （リポジトリ名は入れません。ユーザー名までです）

5. 右上の **「Deploy」** を押す

### 3-4. APIキーを登録する

1. Worker の画面に戻り、**「Settings」**（設定）タブを開く
2. **「Variables and Secrets」**（変数とシークレット）を探す
3. **「Add」**（追加）を押し、次のように入力

   | 項目 | 入力する内容 |
   |---|---|
   | Type（種類） | **Secret**（シークレット）を選ぶ |
   | Variable name（変数名） | `GEMINI_API_KEY` |
   | Value（値） | 手順2でコピーしたAPIキー |

4. **「Deploy」** を押して保存

> `Secret` を選ぶのが重要です。`Text` にすると画面上でキーが見えてしまいます。

### 3-5. 動いているか確認

ブラウザで、メモしたWorkerのURLをそのまま開いてください。

```json
{"ok":true,"service":"meishi-ocr","model":"gemini-3.5-flash-lite"}
```

このような表示が出れば成功です。

## 4. GitHub に上げて公開する

### 4-1. リポジトリを作る

1. https://github.com/new を開く
2. **Repository name** に `meishi-ai-demo` と入力
3. **Public**（公開）を選ぶ ※GitHub Pagesの無料公開にはPublicが必要です
4. **「Create repository」** を押す

### 4-2. ファイルを上げる

1. できたリポジトリの画面で **「uploading an existing file」** というリンクを押す
2. `index.html` `css` フォルダ `js` フォルダ をまとめてドラッグ＆ドロップ
3. 下の **「Commit changes」** を押す

> `worker` フォルダは上げなくても構いません（上げても問題はありません。
> APIキーは入っていないためです）。

上げ終わると、こういう構成になります。

```
meishi-ai-demo/
├── index.html
├── css/style.css
└── js/config.js, storage.js, gemini.js, app.js
```

### 4-3. GitHub Pages をオンにする

1. リポジトリの **「Settings」** タブ → 左メニューの **「Pages」**
2. **Source** を **「Deploy from a branch」** にする
3. **Branch** を **`main`**、フォルダを **`/ (root)`** にして **「Save」**
4. 1〜2分待つと、ページ上部にURLが表示されます

   ```
   https://あなたの名前.github.io/meishi-ai-demo/
   ```

---

## 5. 接続先を設定する

最後に、画面とWorkerをつなぎます。**書き換えるのは1ファイル・1行だけです。**

1. GitHub のリポジトリで `js/config.js` を開く
2. 右上の鉛筆マーク（Edit this file）を押す
3. 次の行の `""` の中に、手順3-2でメモしたWorkerのURLを貼り付ける

   ```js
   API_ENDPOINT: "https://meishi-ocr.あなたの名前.workers.dev",
   ```

   末尾に `/` は付けません。
4. **「Commit changes」** を押す

1分ほどでページに反映されます。

## 6. 動作確認

`https://あなたの名前.github.io/meishi-ai-demo/` を開いてください。

### ✅ 確認する項目

| 見るところ | 正しい状態 |
|---|---|
| 左下の接続表示 | 緑色で「● 接続できました（モデル: …）」 |
| ダッシュボード | 人物・組織・名刺の数が「0」で表示される |
| 左メニュー | 「人物」「人脈」「AI検索」が灰色（Phase 2以降のため） |

### ✅ 名刺を読み取ってみる

1. 左メニューの **「名刺登録」** を押す
2. 点線の枠を押して、**架空の名刺画像**を選ぶ
3. 数秒待つと「読み取り結果の確認」画面になる
4. 項目の右端に **AI** と表示されていることを確認（＝名刺から読み取った値）
5. どこか1つを書き換えると、表示が **修正** に変わることを確認
6. **「この内容で登録する」** を押す
7. ダッシュボードに戻り、人物の数が「1」に増えていることを確認

ここまで確認できたら **Phase 1 は完成** です。

### スマートフォンでも試す

同じURLをスマートフォンで開き、「名刺登録」を押すと**カメラが起動**します。
展示・発表ではこの動きが分かりやすいと思います。

## 7. うまくいかないとき

エラーが出たら、まず**メッセージの文面**を確認してください。原因が書いてあります。

| 表示されるメッセージ | 原因 | 直し方 |
|---|---|---|
| 接続先が設定されていません | `js/config.js` が空 | 手順5をやり直す |
| サーバーに接続できませんでした | URLが違う／Workerが止まっている | URLの綴り、末尾の `/` を確認 |
| このURLからの呼び出しは許可されていません | `ALLOWED_ORIGINS` が違う | 手順3-3。ユーザー名の綴りを確認 |
| APIキーが設定されていません | Cloudflareへの登録漏れ | 手順3-4。変数名は `GEMINI_API_KEY` |
| APIキーが正しくありません | キーの貼り間違い | AI Studioでキーを作り直す |
| モデル "…" が見つかりません | モデル名が古い | `worker.js` の `MODEL` を確認 |
| 利用回数の上限に達しました | 短時間に使いすぎ | 数分待つ |
| AIが応答を返しませんでした | 画像が不鮮明 | 明るい場所で、名刺全体が入るように撮り直す |

**それでも直らないときの調べ方**

ブラウザで `F12` キー（Macは `Command + Option + I`）を押すと開発者ツールが開きます。
`Console` タブに赤い文字でエラーが出ていれば、その文面をそのまま共有してください。

## 8. ファイルの役割

| ファイル | 役割 | 今後さわる場面 |
|---|---|---|
| `index.html` | 画面の骨組み | Phase 2で「人物」画面を追加するとき |
| `css/style.css` | 見た目 | 配色や文字サイズを変えるとき |
| `js/config.js` | 接続先の設定 | **あなたが編集する唯一のファイル** |
| `js/storage.js` | データの保存 | Phase 6でPostgreSQLに移すとき |
| `js/gemini.js` | Workerの呼び出し | Phase 5でAI検索を足すとき |
| `js/app.js` | 画面の動き | 各Phaseで少しずつ追加 |
| `worker/worker.js` | AIへの問い合わせ・APIキーの保管 | モデルを変えるとき |

### データの構造

設計書 §8 のテーブル定義をそのまま使っています。

```
organizations   組織
persons         人物
business_cards  名刺
relationships   人物同士の関係    … Phase 3で使用
interactions    交流の記録        … Phase 3で使用
topics          専門分野          … Phase 2で使用
person_topics   人物と専門の対応  … Phase 2で使用
```

Phase 1では前の3つだけを使いますが、残りも空の状態で用意しています。
「JSONで書き出す」で出力したファイルは、そのままPostgreSQLへの移行元にできます。

### AIに守らせているルール

設計書 §6・§7 のルールは、ブラウザ側ではなく **Worker側** に書いてあります。
利用者が書き換えられない場所に置くことで、ルールが必ず守られるようにしています。

画面の上でも「事実と推論の分離」を守っています。

- 名刺から読み取った値には **AI**、人が直した値には **修正** と表示する
- AIが読み取りに迷った箇所は「AIの注記」として別枠に出し、項目には混ぜない
- 同姓同名がいても自動で結合せず、注意を出すだけにする

## 注意

- **GitHub Pages は誰でも閲覧できます。実在する方の名刺は登録しないでください。**
- データはブラウザの中だけに保存されます。他の端末とは共有されません。
- 保存容量は約5MBです。名刺画像込みで30〜50枚が目安です。
  超える場合はPhase 6でIndexedDBまたはサーバー保存に切り替えます。
- 本番運用では、認証・アクセス権限・操作ログが必要です（設計書 §21）。
